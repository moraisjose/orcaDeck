How the mascot works

The mascot (nicknamed "the puppy" while building it) has exactly four moods, each tied to the aggregate state across every session on the board — never a single card. Every part is always in the DOM; only a data-mood attribute changes, the same mood-machine idea Clawdeck's crab uses. Color lives in the state icon beside the clock and on the cards, not on the mascot itself — the mascot is always solid white; only its motion changes.

Idle (asleep)

Trigger: either the panel has never successfully loaded any data yet (first load), or it has loaded data and there are zero agents running anywhere at all.

Looks like: eyes closed, small "zzz" marks floating above.

Duration: continuous — holds until a session starts working, needs attention, or the first Done session appears.

Working

Trigger: at least one session is busy — actively working, or only monitoring a background task — and nothing anywhere needs attention (working never outranks attention).

Looks like: eyes open, a continuous gentle bob, the side fins flap and the tail tabs wiggle.

Duration: continuous — lasts exactly as long as at least one session is working.

Needs attention

Trigger (highest priority — outranks everything else): at least one session's agent genuinely needs a human, which is exactly Orca's own permission status and nothing else: state:"blocked" or state:"waiting". Also triggers if orcad itself becomes unreachable or errors after data had already loaded once — that's something to go check too.

Not this: workingMode:"monitoring" counts as working (Orca mints it when the turn is done but a background task or session cron is still running — its own label is "Monitoring background tasks"), and interrupted:true counts as finished (someone pressed Ctrl+C). Reading either as attention is what used to pin the whole deck here permanently, which in turn meant the Bounce below could never fire.

Looks like: eyes narrow and worried, a continuous small side-to-side shiver.

Duration: continuous — holds until every such session is resolved (answered, or orcad reconnects).

Done

Trigger: nothing is working and nothing needs attention, but at least one agent has run somewhere (so it isn't truly empty) — the default "nothing left to do" pose.

Looks like: eyes open, calm — no special animation.

Duration: continuous — holds until something starts working, needs attention, or every session disappears entirely (then it's Idle instead).

Bounce (one-shot, on top of Done)

Trigger: the exact instant any one session lands on Done — tracked per worktree, not deck-wide. It is an event, not a mood: a session finishing while three others still need attention still hops, then settles straight back into the worried pose. A session that was interrupted with Ctrl+C doesn't count as finishing, and neither does a session first seen already Done (nobody watched that happen).

Looks like: two quick whole-body hops.

Duration: ~800ms one-shot, on top of whatever mood is showing. It cannot repeat mid-flight, and a session that stays Done doesn't re-fire — only the next session to finish does.

Petting (one-shot, on top of any mood)

Trigger: someone touches or clicks the mascot. Purely a reaction to a human — it reflects nothing about any session, and it fires whatever the mascot is currently doing.

Looks like: it leans into the side you touched, its eyes turn content (^ ^), and a small heart drifts up off that same side. Every preview on this page is a live mascot — pet any of them.

Duration: ~600ms one-shot. The mood is never changed, only briefly overridden, so it goes straight back to working, needs-attention, done or asleep on its own — there is no state to restore. Petting again mid-flight restarts cleanly.

Under prefers-reduced-motion the lean and the heart are silent like the rest of the mascot, but the content eyes still swap in — asking for less motion shouldn't mean touching it does nothing.

The priority ladder

Checked top to bottom, every poll — the first match wins, exactly like Clawdeck's own crab mood ladder:

  1. Never successfully loaded any data yet → Idle
  2. orcad unreachable / a render error, after data had already loaded once → Needs attention
  3. Any session needs attention right now → Needs attention
  4. Any session is working or monitoring → Working
  5. Zero agents running anywhere at all → Idle
  6. Otherwise (only finished sessions) → Done

Neither one-shot is on this ladder. The Bounce is an event fired per worktree and Petting is a response to a human, so both play on top of whichever mood the ladder settled on.

Per-session statuses

Cards and agent rows use Orca's own status ladder rather than the four moods above, in Orca's own order — read out of its worktree-status.js:

  1. Needs attention — state:"blocked" / "waiting"
  2. Working — state:"working"
  3. Monitoring — state:"working" + workingMode:"monitoring": turn done, background task or cron still running
  4. Interrupted — state:"done" + interrupted:true: a human pressed Ctrl+C
  5. Done — state:"done"
  6. No recent update — any non-done status older than 30 minutes, matching Orca's own AGENT_STATUS_STALE_AFTER_MS decay, so a pane whose hook stream died stops claiming to be live work
